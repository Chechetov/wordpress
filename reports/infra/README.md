# Реестр учётных записей сетки

Единый список: что где заведено и что этим держится. Завели новый аккаунт —
строка сюда сразу же, иначе через полгода никто не вспомнит, зачем он был.

## Почему не отдельная почта Gmail под каждый сайт

Десяток ящиков руками — работа, которая не кончается, и половина из них
теряется. Вместо этого одна почта на своём домене с включённым **catch-all**:
адрес придумывается на ходу, заводить ящик не нужно, всё падает в один инбокс.

Домен для этого — `4pbn.com`: почта на нём уже поднята (свой `mail.4pbn.com`
на Beget, SPF настроен). Достаточно включить catch-all в панели, и адреса
вида `cf2@4pbn.com`, `cf3@4pbn.com` заработают сами, без регистраций.

Оговорка на будущее: имя `4pbn.com` прямым текстом называет схему, и оно уже
зашито в старые выгрузки WordPress (`mu-th-ur@4pbn.com` стоит автором записей).
Публично оно нигде не светится, так что на анти-аффилиацию это не влияет, но
для нового инфраструктурного домена лучше взять нейтральное имя.

## Чего здесь нет и быть не должно

**Паролей.** Файл лежит в git. Пароли — в менеджере паролей, здесь только адрес
и назначение.

## Как этим пользоваться

Главная колонка — «Что держит». По ней сразу видна цена потери доступа:
из строки Timeweb, например, читается, что за 472 рубля висят 19 живых доноров.

Разделитель — точка с запятой, потому что внутри значений есть запятые.

## Конвейер аккаунтов Cloudflare

Регистрацию делает человек — это не автоматизируется, и не потому что лень:
Cloudflare прямо запрещает массовое автоматическое создание аккаунтов и
пачками их банит. А туда мы кладём DNS всей сетки, так что рисковать нечем.

Всё, что после регистрации, делает `cf_distribute.py`.

### Один аккаунт — три минуты

1. Адрес почты берётся из catch-all: `cf6@4pbn.com`, ящик заводить не нужно.
2. Регистрация на dash.cloudflare.com, подтверждение письма.
3. **My Profile → API Tokens → Create Token → Custom token**, права:
   `Account → Zone : Edit`, `Zone → DNS : Edit`, `Zone → Zone Settings : Edit`.
   Область — All accounts / All zones.
4. Токен в `.env` строкой `CLOUDFLARE_TOKEN_CF6=...` (файл в gitignore).
5. Строка в `accounts_registry.csv`: адрес, что держит, дата.

### Дальше само

Вписать домены и номер аккаунта в `reports/recovery/cf_accounts_split.csv`, затем:

    python3 cf_distribute.py --ip 157.228.135.19 --dry-run
    python3 cf_distribute.py --ip 157.228.135.19

Скрипт заведёт зоны в нужных аккаунтах, поставит проксируемые A-записи на `@` и
`www`, включит SSL Full и впишет полученные пары NS обратно в тот же CSV —
оттуда их и переносят к регистратору.

### Сколько аккаунтов имеет смысл

Не больше, чем реально нужно. Держать про запас два десятка пустых аккаунтов
смысла нет: они всё равно получат NS только когда в них появятся зоны, зато
растёт шанс, что Cloudflare свяжет их между собой и прикроет разом. Заводится
аккаунт под конкретную партию доменов — тогда и связывать особо нечего.

### Про перенос зоны между аккаунтами

Один домен не может лежать в двух аккаунтах Cloudflare одновременно. Перенос —
это удалить зону в старом аккаунте и завести в новом, то есть NS сменятся и их
придётся заново прописывать у регистратора. Поэтому раскладку лучше продумать
до первой смены NS, а не после. Скрипт сам такие зоны не трогает — только
сообщает о них.
