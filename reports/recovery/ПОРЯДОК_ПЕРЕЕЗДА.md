# Порядок переезда домена на новый сервер

Уточнён на `yellodigital.ru` 31.08.2026. Новый сервер — `157.228.135.19`.

## Что выяснилось на первом домене

- Домен живёт в своём аккаунте Cloudflare, зона активна, NS совпадают с
  делегированием у регистратора. Правка A-записи работает мгновенно.
- SSL стоял **Flexible** в автоматическом режиме. Его надо переключить на
  **Full**: новый origin отвечает по HTTPS, и на Flexible получается петля.
- Always Use HTTPS уже был включён — проверять, но, скорее всего, не трогать.
- На зоне есть custom-правило **Search Protection** с действием Managed
  Challenge. Оно пропускает поисковых ботов по ASN и свои IP по списку:

      (not cf.client.bot and not ip.src in {...свои IP...})
      or (cf.client.bot and not ip.geoip.asnum in {15169 396982 13238 208722 212066})

  ASN: 15169 Google, 396982 Google Cloud, 13238 Яндекс, 208722 Nebius,
  212066 Buyuk Reklam Cozumleri. Для SEO всё в порядке — краулеры проходят.
  В списке своих IP стоял **старый origin**, его надо заменить на новый.
- Белый список только по IPv4. У нового сервера есть IPv6, и по нему он ловит
  челлендж. **Все проверки снаружи гонять с `curl -4`.**

## Порядок на каждый следующий домен

1. **Вход.** Пользователь логинится на dash.cloudflare.com под учёткой домена
   (`reports/nikita.tsv`, колонки почта и пароль). Пароли вводит только он.
2. **Токен.** Manage account → Account API tokens → Create a token →
   Start from scratch. Настройки:

   | поле | значение |
   |---|---|
   | Token name | `pbn-repoint` |
   | Область политики | **All Domains** |
   | Права | DNS **Edit**, Zone **Read**, Zone Settings **Edit**, Zone WAF Rules **Edit** |
   | Expiration | No expiration |
   | Client IP filtering | пусто |

   Кнопку «Create token» жмёт пользователь, значение вставляет в
   `reports/recovery/cf_access.csv` (третья колонка, файл в gitignore).
3. **DNS и SSL — командой:**

       python3 cf_repoint.py --ip 157.228.135.19 --only ДОМЕН --dry-run
       python3 cf_repoint.py --ip 157.228.135.19 --only ДОМЕН

   Ставит `@` и `www` на новый IP проксируемыми, `ssl=full`,
   `always_use_https=on`.
4. **Белый список правила — командой:**

       python3 cf_allowlist_swap.py --old 45.95.203.95 --new 157.228.135.19 --only ДОМЕН --dry-run
       python3 cf_allowlist_swap.py --old 45.95.203.95 --new 157.228.135.19 --only ДОМЕН

   Если на зоне другого старого IP — посмотреть выражение правила и подставить
   нужный. Скрипт меняет только эту подстроку, действие и порядок не трогает.
5. **Проверка:**

       curl -4 -sS -o /dev/null -w '%{http_code}\n' -A 'Mozilla/5.0' https://ДОМЕН/
       ssh -i ~/.ssh/pbn_recovery root@157.228.135.19 \
         'curl -4 -sS -o /dev/null -w "%{http_code}\n" https://ДОМЕН/'

   С сервера должно быть 200 (он в белом списке). С чужого IP — 403 с
   челленджем, и это нормально, так задумано.
6. **Запись в журнал:** строка в `reports/recovery/repoint_log.csv`.
